# 記事の画像と参考URL

記事は承認・予約・公開の前に画像が1枚以上必要です。枚数の固定上限はありません。画像本体は認証付きの非公開D1に保存し、公開GitHubには入れません。1枚はPNG/JPEG/WebP、1MB以内です。

画像はSHA-256で識別し、登録後の画像データは変更・削除できません。画像の一覧・順序・説明・キャプション・出典と参考URLは最終版のハッシュに含みます。変更すると承認・予約・公開許可が失効します。以前の版の画像は監査のため保持します。

## 夜間制作の手順

1. `.state/drafts/YYYY-MM-DD.json` に3記事を制作します。本文とは別に `images` と `sources` を用意します。
2. `.state/diagram-specs/YYYY-MM-DD.json` に記事ごとの図解仕様を保存します。仕様は `[[key,見出し,補足,[手順1,手順2,手順3],[説明1,説明2,説明3]], ...]` です。見出し35文字以内、手順各14文字以内、説明各22文字以内、keyは英小文字・数字・ハイフンです。図解は記事に即した内容にします。
3. `node scripts/create-article-diagrams.mjs "$PWD/.state/images/YYYY-MM-DD" "$PWD/.state/diagram-specs/YYYY-MM-DD.json"` で画像を生成し、見た目を確認します。空の装飾や記事と無関係の画像で埋めません。写真やイラストのほうが適切なら、利用権限のある素材や画像生成を使います。
4. `node --env-file=.env scripts/upload-image.mjs .state/images/YYYY-MM-DD/key.png` で非公開保管し、返る `id` を記事の `images` に設定します。例：`[{"id":"画像のSHA-256","alt":"内容を説明する代替テキスト"}]`。
5. 実際に開いて内容を確認した公式資料・一次資料があれば、`sources: [{"title":"資料名","url":"https://…"}]` に記録します。記事独自の方法を資料に書かれた方法だと扱わず、出典を作らないでください。
6. `content` で検証してから `import-batch.mjs` で未承認のまま取り込みます。画像がない記事の機械取り込みは拒否されます。

1枚目の画像をnoteの見出し画像にも設定し、すべての画像を本文末尾にも掲載します。見出し画像は通常のアップロード画面から保存し、再読み込みして設定が残っていることを確認してから公開に進みます。画像の順番を変えると見出し画像も変わるため、承認は失効します。参考URLは本文の末尾にも掲載します。noteの画面変更で画像の挿入や照合ができない場合、公開前に停止します。既存の公開記事を自動で編集しません。
