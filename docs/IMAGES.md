# 見出し画像と本文画像

未公開記事は、本文とは別の見出し画像1枚と、タイトル・本文に合う本文画像1枚以上が必要です。本文画像の枚数に固定上限はありません。登録形式はPNG/JPEG/WebP、1枚1MB以内です。画像本体は非公開D1へ保存し、公開GitHubには置きません。

見出しは一覧で好印象になる、明るく親しみやすい横長画像を記事ごとに新作します。タイトルが扱う場面・物・行動を絵にし、無関係な装飾や全記事共通の汎用画像で済ませません。本文の図解を見出しに使い回しません。見出し画像と本文画像のファイルが同じ場合は拒否します。タイトルとの適合と見た目は実際に画像を見て確認し、最終承認は所有者が行います。

画像のSHA-256、説明、キャプション、クレジット、参考URLは承認対象です。見出し画像を変更すると承認・予約・公開許可が失効します。履歴の画像は監査のため保持します。公開済みの記事は自動変更しません。

## 夜間制作

1. 非公開の `.state/drafts/YYYY-MM-DD.json` に3記事を制作します。
2. 各タイトルと本文を読み、見出し画像を1枚ずつ別々に生成します。明るい背景、前向きで親しみやすい色、一覧でも伝わる主題、横長で端を切られても主題が残る余白を使います。本文画像とは別の構図・役割にします。内蔵の画像生成機能を使い、勝手に有料APIへ切り替えません。出力を必ず見て、主題、手や顔、文字・数字、切れ、視認性を確認します。
3. 生成画像を `.state/images/YYYY-MM-DD/covers/` へコピーします。必要ならローカルの形式変換でJPEG化・縮小し、1MB以内で画質を確認します。画像生成の原本は保持します。
4. 本文の手順を説明するオリジナル図解などを1枚以上用意します。図解仕様は `.state/diagram-specs/YYYY-MM-DD.json` に `[[key,見出し,補足,[手順1,手順2,手順3],[説明1,説明2,説明3]], ...]` で保存します。見出し35文字以内、手順各14文字以内、説明各22文字以内、keyは英小文字・数字・ハイフンです。
5. `node scripts/create-article-diagrams.mjs "$PWD/.state/images/YYYY-MM-DD/body" "$PWD/.state/diagram-specs/YYYY-MM-DD.json"` で本文図解を描画し、内容と見た目を確認します。写真・イラストが適する場合は権利のある別の画像を使えます。
6. 各画像を `node --env-file=.env scripts/upload-image.mjs .state/images/YYYY-MM-DD/covers/key.jpg` などで非公開保管し、返されたidを記事に設定します。
7. `cover: {id,alt,credit,sourceUrl}` が見出し画像1枚、`images: [{id,alt,caption,credit,sourceUrl}, ...]` が本文画像です。altは内容の説明、任意項目は省略できます。AI生成画像のクレジットは「余白ラボ（AI生成）」とします。cover.idをimagesへ重複させません。
8. 確認済みの公式資料・一次資料がある場合、`sources: [{title,url}]` にHTTPSリンクを保存します。記事独自の方法を資料に記載された手順だと扱いません。
9. `src/core.mjs` のcontentで形式を検証し、`import-batch.mjs` で未承認のまま取り込みます。画像が足りない場合は取り込まず報告します。

見出しはnoteの見出し画像欄へ、本文画像は本文末尾へ掲載します。noteで保存して再読み込みし、見出しと本文画像がそれぞれ正しく保存されたことを確認してから公開に進みます。承認済みの画像と一致しなければ公開しません。
