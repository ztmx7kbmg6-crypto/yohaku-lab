# 余白ラボ：使い始める手順

## カード不要の初回ログイン

[編集室](https://ztmx7kbmg6-crypto.github.io/yohaku-lab/)を開き、「初回・復旧用の管理者キーでログイン」の管理者キー欄に、Macの `.state/owner-setup.txt` に保存されたキーを入力します。キーはランダムな256ビットで、サーバーにはSHA-256ハッシュだけを保存しています。キーをチャットやGitHubへ送らないでください。

ログイン後、「設定 → この端末にパスキーを登録」で、ご本人の端末認証を使って登録してください。iPhoneでも同じ編集室を開き、iCloudキーチェーン等を通じて利用できるパスキーを使うか、管理者キーでログインしてパスキーを追加できます。署名・RP ID・Origin・ユーザー検証・1回限りのチャレンジをサーバーで検証します。ログインセッションは30分間、ブラウザのメモリだけに保持します。再読み込みするとログインし直す場合があります。管理者キーは復旧用にも使うため、安全に保管してください。

Zero Trust・Supabaseの登録やカード登録は必要ありません。Cloudflare Workers/D1の無料枠を使います。利用上限はCloudflareの設定を確認してください。有料プランへの変更はしていません。

## iPhoneの通知

Safariで編集室を開く → 共有 → ホーム画面に追加 → そのアイコンから起動 → ログイン → 設定 → 通知を有効にする。iOS/iPadOS 16.4以降とHTTPSが必要です。Macで通知プロセスが動いている間、更新イベントが配信されます。端末への実到達は実機で別途確認してください。

通知内容は「編集室に更新があります」のみ。ロック画面に記事本文やタイトルを送信しません。

## Macのnote専用ログイン

in-app browserのnoteログインは、常駐処理用のChromeとは別です。Cookieを抜き出して移植する方式は使いません。

`scripts/note-login.command` をダブルクリックすると、Mac処理専用のChromeが開きます。余白ラボのアカウントで本人がログインし、ターミナルに戻ってEnterを押します。パスワードをチャットやターミナルの入力欄に記載しないでください。ログイン状態はGit対象外の `.auth/note-profile` に保存されます。

## 処理モード

`.env` はMac専用、権限600、Git対象外です。

- `NOTE_MODE=fixture`: 外部通信を遮断した専用画面への入力テスト。
- `NOTE_MODE=notify-only`: 通知配信と通信状況の更新だけ。記事の予約を取得しません。
- `NOTE_MODE=note-dry-run`: 専用Chromeでnoteに下書き入力し、価格・タグ・有料境界まで確認します。投稿ボタンは押しません。
- `NOTE_MODE=note-live`: 投稿アダプタを使います。Mac側とWorker側の `NOTE_LIVE_ENABLED=true` が両方必要です。機能は接続済みで、初期状態は全体停止中です。

実行例：`NOTE_MODE=notify-only node --env-file=.env scripts/agent.mjs`。

記事は本文の承認に加えて、同じ最終版に対する「note公開を許可」が必要です。修正すると両方失効します。予約時刻・全体停止・リース・重複・公開許可を直前に検査します。公開の許可証は短時間・1回限りで、クリック結果が不明なら要確認に隔離し、自動再投稿しません。

投稿アダプタの固定設定はAI学習提供OFF、自動翻訳OFF、有料記事の返金申請受付ONです。本文はテキストと改行に対応し、画像・埋め込み・複雑な装飾には未対応です。有料境界は段落の先頭を指定してください。

公開後の画面遷移が想定と違う場合は、実際には公開されていても「要確認」になります。既存URLとnote側の公開状態を照合してください。確認せず再投稿してはいけません。

## 夜間制作

午前2時JSTに、Codexの「余白ラボ：夜間の3原稿制作」タスクを登録しました。MacとCodexの実行環境が利用できる必要があり、実行には利用枠等の制約があります。無料1本・200円2本の原稿を非公開バックエンドへ未承認で取り込みます。公開・承認・停止解除は行いません。初回の定時実行は未確認です。

一括取り込みは `node --env-file=.env scripts/import-batch.mjs .state/drafts/YYYY-MM-DD.json`。その日の控えが既にある場合は二重取り込みを止めます。途中中断した場合も自動再試行せず照合が必要です。

## 検証状況

- 新Cloudflareアカウントへの配置、管理者キーによるログイン、未ログインでの記事閲覧拒否を確認。
- 実noteでの非公開下書き保存、200円設定、有料境界の移動、タグ入力をin-app browserで確認。実投稿は0件。
- 投稿直前の許可・停止・期限・重複・改訂による失効を単体テスト。
- 専用Chromeでの実機dry-run、パスキーの実端末登録を確認済み。iPhone通知到達と初回の本番公開は未確認。
- 本番機能は接続済み。jp.yohaku.agentを登録し毎分の通信成功を確認。全体停止中のため記事は処理しない。

## 毎日の操作

1. 記事一覧で本文・価格・有料境界を読む。
2. チェックを入れ「この最終版を承認」。続いて「この最終版のnote公開を許可」で公開を明示許可する。
3. 「予定」で承認済みの無料1本・200円2本を選び、予定日を指定して時刻を決める。JSTの10–12時・15–18時・19–22時から、2時間以上あける。経過した枠は使わない。
4. 初期状態は全体停止なので「投稿処理を再開」を押す。以後は条件が揃った記事だけ予約時刻に処理する。
5. 中止する場合は「すべて停止」。既に公開操作に入った処理は完了する場合がある。

Macは電源・ネットワーク・macOSのログインセッションが必要。スリープ中やログアウト中は投稿できない。常駐処理は画面表示ありの専用Chromeを使う。予約から15分以上遅れた記事は自動でまとめて投稿せず失敗にする。

修正依頼は午前2時のタスクで対応する。自分で編集した場合も、承認・公開許可・予約は失効する。修正版の保存を通知し、再承認が必要になる。修正依頼の即時AI処理を保証するものではない。

noteの下書きをアプリ外で直接編集した場合は、編集室の原稿にも反映して再承認する。投稿前にアプリとnote側を別々に変更しない。
